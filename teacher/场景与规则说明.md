# 有人—无人协同探测仿真器：场景与规则说明

本文件从项目《有人-无人协同探测场景与规则库设计方案（V2.7，聚焦版）》整理而来，
只说明任务场景、传感器/航迹模型和规则判定。代码副本不包含训练脚本、策略网络、
实验结果或检查点。

## 1. 任务概览

任务是在固定二维空域内，用 1 架有人机和 3 架无人僚机，对同时进入的红方编队进行协同发现与跟踪。红方是脚本化目标，只按预设机动飞行，不根据蓝方行为反应。蓝方需要在红机越过截止线之前完成稳定跟踪判定。

## 2. 空域、兵力与初始部署

| 项目 | 设定 |
|---|---|
| 空域 | 160 km（东西）×120 km（南北）的矩形；x 向东、y 向北 |
| 蓝方 | 1 架有人机 + 3 架无人僚机；僚机是学习接口，二维质点模型 |
| 有人机 | 脚本化固定 CAP，中心 (15,60) km，跑道腿 x±5 km、y±10 km；不参与学习，也不计 MOR/MAR 接近账本 |
| 红方 | 基准 K=4；容量扫掠可用 K∈{2,4,6,8,12}；所有目标 t=0 已在场 |
| 红方初始位置 | x∈[150,160] km 的探测区东缘，按车道成对交错进入 |
| 蓝方初始位置 | x≈20 km、y≈20/60/100 km，向东进入 |
| 回合 | 决策步长 1 s，最长 900 s（15 min） |

功能分区：x<40 km 为截止线后区域；40≤x≤110 km 为跟踪区，责任目标要求严格 `age<2 s`；110<x≤160 km 为探测区，责任子区内目标要求严格 `age<5 s`。红机越过 x=40 km 且尚未完成判定，回合立即失败。

红方脚本包含直线、S 形、随机转弯、waypoint、领先时 regain 回转、同高度避让和边界抑制；巡航约 0.75 Ma，机动速度范围 0.6–0.9 Ma，转弯率上限 8°/s。红方没有 RWR、告警脱离、干扰或武器。

## 3. 接近代价与任务终局

为了防止蓝机贴近红机换取探测概率，僚机与红机之间设置两级距离代价：

- MOR=60 km：进入后按距离梯度持续扣分；
- MAR=40 km：进入后施加更重的持续惩罚。

裁判的接近违规、奖励和终局使用红方真值；每架僚机的安全/观测仍只使用自己的航迹簿和队友指针。有人机固定在安全 CAP 区域，不计入 MOR/MAR 学习账本。

任务成功：全部 K 个红机都在跟踪区内完成连续 30 s、逐秒检查且每秒 `age<2 s` 的稳定窗；完成后永久记为已判定。任务失败：任一未判定红机满足 x<40 km。超时：900 s 仍未全部判定。

## 4. 传感器与航迹簿

雷达瞬时波束为 ±7.5°，最大作用距离 80 km。扫描扇区半角可取 ±7.5°、±15°、±30°、±45°、±60°，对应完整帧周期 0.5、1、2、3、4 s；每个波位驻留 0.5 s。SEARCH 只能使用 ±45°/±60°，TRACK 只能使用 ±7.5°/±15°/±30°，档位切换至少完成一个帧周期。

命中按距离和离轴角进行概率抽取：归一化距离不超过 0.5/0.8/1.0 时，基础探测概率为 0.9/0.6/0.3，超过最大距离为 0；离轴角还会降低有效距离。每架僚机只维护自己的航迹簿，不做跨机航迹融合。

航迹状态为 `detected → tentative → confirmed → coast → dropped`：6.5 s 内至少两次本机命中成 tentative；随后连续 5 s、更新间隔不超过 1.6 s 才 confirmed；age>8 s 降权，age>13 s 注销。有效更新使协方差收窄，外推使不确定度按过程噪声膨胀。

## 5. 蓝方角色、责任和接口

僚机有两个战术角色：

- **SEARCH**：宽扇区巡逻，优先覆盖本责任子区最久未扫描单元；获得目标责任后转 TRACK。
- **TRACK**：窄扇区精跟，按责任目标外推位置指向，并以 62 km 为跟踪距离中心；稳定窗完成、丢批或责任变更后回 SEARCH。

责任子区沿 y 方向三等分，每区 40 km，初始左/中/右分配。目标责任可随目标跨区移动；新责任机须在 80 km 能力范围和可用扇区内。责任申请通过有人机节点的分配表出口体现，初次批复延迟为 0 s。链路 1 Hz、延迟 1 s；链路降级时保持已有责任，不得新申请或交接。

代码动作接口是每架僚机 3 个连续量（转向、速度、扇区轴微调）加 3 个离散量（角色、扇区档位、责任指针）。接口会屏蔽角色—档位非法组合，并将连续控制裁剪到 [-1,1]。

## 6. 规则库

规则按 P0（硬安全）到 P5（弱效率）分层。代码实现共 21 个规则谓词；设计文档早期表头写作 17 条，后续版本增加了 M05 等闭合项，故以代码实际判定为准。

| 编号 | 层级 | 判定含义 |
|---|---|---|
| S01 | P0 | 控制请求超出包线（连续动作绝对值超过 1） |
| S02 | P0 | 预测 3 s 内任意蓝机对最小间隔小于 2 km |
| S03 | P0 | 蓝机越出 160×120 km 空域，或预测 5 s 将出界 |
| S04 | P1 | 僚机与红机真值距离小于 MAR=40 km |
| S05 | P2 | 僚机与红机真值距离小于 MOR=60 km，记录距离残差 |
| C01 | P3 | 同一目标出现多个责任机 |
| C02 | P4 | 责任子区探测区段内、当前可达单元的最近扫描间隔超过 120 s |
| C03 | P3 | 同一目标 30 s 滑窗内责任变更超过 1 次；现任违反 C04 时的紧急交接豁免 |
| C04 | P4 | 责任机距离目标超过 80 km，或目标不在其扇区可用半宽内；超过 5 s 未处理则违规 |
| C05 | P3 | 链路降级时仍申请新责任或发起交接 |
| M01 | P4 | 探测区责任目标的航迹 age 达到 5 s 或更大 |
| M02 | P3 | 跟踪区责任目标的航迹 age 达到 2 s 或更大 |
| M03 | P4 | 已接责任的 30 s 稳定窗长期没有推进且未交接 |
| M04 | P1 | 红机越过 x=40 km 时仍未完成稳定跟踪，终止失败 |
| M05 | P4 | 跟踪区已有航迹但没有责任归属（5 s 宽限后闭合自由搭车漏洞） |
| I02 | P1 | 无迹或单点 `detected` 状态却申请责任；`tentative`（至少两次命中）允许申请 |
| I03 | P4 | 使用 age>8 s 的过时航迹申请责任或精跟 |
| E01 | P2 | 未完成完整帧就切换雷达档位 |
| E02 | P4 | 角色驻留不足 5 s 就切换 |
| E03 | P5 | 60 s 滑窗新增覆盖面积/飞行位移低于 5 km²/km，判定反游荡 |
| F01 | P2 | 10 s 上行丢包率超过 30%，进入链路降级 |

说明：S04/S05 的违规仍正常上报，但不重复计入通用 w8 罚单；接近代价走专用 MOR/MAR 通道。安全护盾不在本交付副本中，因它属于控制方法层；本仿真环境仍可独立完成真值规则判定、奖励和终局检查。

## 7. 冲突关系

代码登记 13 对冲突：S04–M02、S05–M02、C01–M02、C03–M02、C02–M01、M01–M02、S02–M02、S03–M02、I02–M02、I03–M02、M04–S04、C01–C03、M05–E03。它们分别表达安全距离、跟踪质量、责任唯一、交接频率、覆盖时效、边界、信息真实性以及“责任闭合与反游荡”的资源竞争。

## 8. 代码目录与最小运行

```
teacher/
├─ 场景与规则说明.md
└─ simulator/
   ├─ run_smoke.py
   └─ aircraft_sim/
      ├─ detect_env.py       # 环境主循环、时间推进、终局与奖励
      ├─ detect_config.py    # 场景参数
      ├─ detect_models.py    # 动作与角色
      ├─ detect_rules.py     # 规则谓词监视
      ├─ radar.py             # 雷达波束与概率命中
      ├─ track.py             # 航迹状态机
      ├─ red_agent.py         # 红方脚本机动
      ├─ models.py            # StepResult
      └─ __init__.py
```

在 `teacher/simulator` 目录安装 `numpy` 后运行：

```powershell
python run_smoke.py
```

该命令创建 K=2、固定种子的环境，执行 5 个空动作步，并打印观测代理数、步数、终局状态和奖励。正式使用时可导入：

```python
from aircraft_sim import DetectAction, DetectEnv
env = DetectEnv()
obs = env.reset({"seed": 7, "k_red": 4})
result = env.step({i: DetectAction() for i in range(env.n)})
```
